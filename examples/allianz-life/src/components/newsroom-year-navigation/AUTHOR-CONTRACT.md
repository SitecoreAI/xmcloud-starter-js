# Press archive navigation

Technical componentName: `NewsroomYearNavigation`. Friendly rendering label: **Press archive navigation**. Fixed variant: Default. This rendering has no data template, datasource, authored year list, or appearance controls. Native definition work creates only the renderer, its variant group, and Default variant. RenderingIdentifier is the only consumed parameter.

The registered server-only SDK hook discovers every qualifying direct child page of Newsroom. Children must match the `YYYY-press-releases` naming and native URL contract and use the verified native Page template `2d50c9b4-9f1e-42ae-aa00-0c85fd2b689e`. Years are ordered newest first. No copied fixtures, client fetching, authored Multilist, or manual-list fallback is used. Add a qualifying native archive page to make it available automatically; edit its own inherited SXA NavigationTitle to change its label.

The server supplies `automaticYears` through the installed SDK ComponentPropsContext under the rendering UID. Its contract is `{ items, complete, status, currentId?, error? }`, using the shared client-safe `AutomaticYear` and `AutomaticYears` types in `src/lib/newsroom-automatic-data.ts`. Ready results require `status: 'ready'` and `complete: true`. The component consumes them with `useComponentProps(rendering.uid)` and preserves the complete server order and original SDK Field objects. Missing, duplicate, malformed, or incomplete results fail explicitly instead of rendering a partial menu. Empty complete results stay empty. The active year and mobile title are determined by matching `currentId` to the native page ID.

The native year page's inherited SXA NavigationTitle supplies both its link label and the active mobile title. The server selects it by the read-backed GUID `4e0720e9-9d50-4ddc-87cf-ecd65e8e94c8`, matching the deployed context breadcrumb selector. Labels preserve original native Field objects and intentional empty values, and render read-only in Pages. Authors edit captions in the owning year page’s NavigationTitle field editor. Page URLs use the existing public link helper and installed SDK Link. Native renderer/base/parameter identities must be read from the target before creation; none are invented here.

The source `m-navigation-secondary`, `nav-sec-list-title`, `nav-sec-list`, `-is-active`, and `m-navigation-secondary-open` classes retain the recovered CSS. Desktop starts at 704px with the centered grey band and active underline. At 703px and below, the title is a native button with aria-expanded/aria-controls; click, Enter, and Space toggle the list without navigation. Escape leaves it open, matching the witness. The sole scoped CSS resets generic button appearance and hides collapsed mobile links from focus. No Sitecore chrome is styled.

Tests use the installed Sitecore SDK, real ComponentPropsContext keyed by rendering.uid, and source HTML/JSON witnesses. The supplied 1024px, 390px collapsed, and 390px expanded JPGs were visually inspected before implementation; original hashes are retained in the source manifest. Source button-versus-anchor semantics are intentionally improved while retaining source visual classes. Native Preview discovery, page qualification, field metadata, complete year readback, runtime/browser geometry, authoring, and publication acceptance remain separate server/native checks. Local rendering tests do not establish those stages.

Run `node --test src/components/newsroom-year-navigation/__tests__/*.test.mjs`, scoped ESLint, and TypeScript checks. The tests generate component maps only in a temporary directory with the actual installed SDK default settings; real generated maps are preserved.
