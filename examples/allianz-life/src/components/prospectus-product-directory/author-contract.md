# Prospectus product directory

This directory automatically lists eligible direct child prospectus pages of the current page. It keeps two ordered single-column striped tables, with editable currentHeading and pastHeading fields on the existing datasource, seeded to Current Products and Past Products. Clearing a heading preserves its native SDK editing metadata and does not restore fixed copy.

Each child page owns two narrow editorial fields: prospectusDirectoryTitle (Single-Line Text) for its exact directory caption, and prospectusDirectoryGroup (Droplist whose Source points to a real options root with two children named exactly current and past). A blank group intentionally excludes a page; membership is never inferred from its title, date, URL, or presence alone. Native sibling enumeration controls order within each group. The runtime preserves that order across cursor pages and never substitutes its own sort-order, name, or GUID tie-break. Native shared __Sortorder only needs adjustment if actual child enumeration differs from the intended order. Links use the returned child-page URL, while derived captions render read-only in Pages. Authors edit prospectusDirectoryTitle on its owning child page in the normal field editor; the original field and metadata remain intact. The widget headings remain editable on the directory datasource. Existing page titles/navigation titles are not repurposed because their recovered values are slugs rather than the exact directory captions.

The request-local SDK server hook enumerates item.children on the current page, exhausts every cursor page including unrelated children, then filters the verified existing prospectus-page template. It checks parent ID and direct native/public paths and preserves complete native field objects and native sibling order. Unknown nonblank groups, missing caption fields, invalid URLs, inconsistent totals/cursors or duplicate IDs produce an unavailable result. Empty groups are allowed. No selected-reference, browser query, source fixture or manual-link fallback exists.
