# Section navigation candidate

Technical componentName: `SectionNavigation`. Fixed variant: Default. This candidate is cloud code only. Native rendering activation awaits readback of the target's existing metadata. There is no datasource, authored link list, new checkbox, appearance field, route exception, or fixture fallback.

The server hook requires `bindings: { pageBaseTemplateId, excludedFilterFieldId, rootParameterName, filterParameterName }`. Every identity/name must be read from the target before binding. The two named rendering parameters must supply the actual section root and selected navigation filter GUIDs. No defaults are assumed. Missing/invalid bindings return an unavailable `unbound` result without any discovery query. Invalid parameter/current/language scope also produces no discovery query. The request's actual layout route item ID and context language scope all reads; Preview versus public visibility is determined by the caller's endpoint and headers, without extra publication/status filters.

The existing per-page “Check to hide in navigation filters” selection is compared with the rendering's selected filter. The page base template establishes inherited membership through `_templates CONTAINS`; exact concrete-template equality would omit inherited pages. The complete native `root.item.children` traversal owns order. A separate complete `_path CONTAINS root` and language-scoped search establishes page membership, selecting `_latestversion EQ "true"` using the same supported version predicate as the existing People and Portfolio searches. This selects the latest language version; it does not add a publication, workflow or layout filter. All pages of both cursors must succeed before any navigation is rendered. Root/current IDs, item paths, parent ownership, counts, uniqueness, stable pagination scope and cursors are checked. Nonpage children are omitted; excluded page children are omitted only through the existing selected filter. Unknown exclusion serialization fails instead of silently including potentially hidden pages.

The hook returns `automaticSectionNavigation: { root, items, currentId, complete, status, error? }` through the installed SDK ComponentPropsContext keyed by rendering UID. It is created once per request via `enrichSectionNavigationComponentMap(map, { getData, fetchOptions, bindings })`, preserving request headers and isolating caches. It does not return credentials, native unfiltered child connections, or error details to the client. There is no client fetch or integrated component query.

The source root link is the generic section-intro label “Overview”. Its URL is the returned native root URL; the label is UI chrome and does not overwrite the root's NavigationTitle. The disclosure heading retains the root's original native SXA NavigationTitle Field object, selected by verified field ID `4e0720e9-9d50-4ddc-87cf-ecd65e8e94c8`. Child captions retain their own same inherited field. This field remains distinct from the project's similarly named caption field. Current state matches the actual native current ID exactly; a deeper or excluded page does not invent an active parent link.

All derived captions use SDK Text with `editable={false}` and all navigation links use SDK Link with `editable={false}`. Authors edit NavigationTitle on each owning page; the candidate neither suppresses nor changes that page's editable field. Native internal URLs are validated independently of fixtures or environment selectors and never derived from titles or slugs. Missing native fields and incomplete data show an explicit unavailable status. Intentionally blank fields stay blank in editing mode and do not get copied fallback labels.

Recovered source classes `m-navigation-secondary`, `nav-sec-list-title`, `nav-sec-list`, `-is-active` and `m-navigation-secondary-open` provide the gray desktop strip, active underline, and 704px desktop breakpoint. At 703px and below, a native button exposes `aria-expanded` and `aria-controls`, and repeated click/Enter/Space activation toggles the list. Scoped CSS resets only generic button appearance and hides collapsed mobile links. No Sitecore chrome selectors are added.

Official native workflow reference: https://doc.sitecore.com/sai/en/developers/sitecoreai/content-modeling-and-presentation/sitecoreai-for-developers/content-editor-items/sites/exclude-a-page-from-the-navigation-menu.html

Native acceptance remains blocked until actual page base template, existing exclusion-field identity/type/serialization, rendering root/filter parameter names, selected filter identity, root/current IDs, Preview query support and complete readback are verified. Source/test witnesses do not establish those native facts. No native schema change, publication, deployment or browser action is part of this candidate.
