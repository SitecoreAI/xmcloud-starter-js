# Prospectus document table

The table automatically lists every ProspectusDocumentRow child of its own page-local datasource. Authors add, edit, reorder, or remove those child records; there is no separate document selection. The existing documents Multilist is retained only as migration evidence and is never a runtime fallback.

The request-local SDK server hook enumerates the native item.children connection, exhausts all cursor pages, verifies datasource ownership by the current page, and filters the verified document-row template while preserving the returned sibling order. It does not sort by field values, names, or IDs. A missing, changed, duplicate or incomplete response produces an unavailable state, never a truncated or stale table. No browser-side query or credentials are used.

Each row retains the four existing independently editable fields: documentLink (General Link), contractNote (Single-Line Text), revisionDate (Single-Line Text), and fileSize (Single-Line Text). Complete native SDK jsonValue objects, deliberately blank dates/sizes, duplicate document captions, contract notes and link behavior remain intact. The table labels, stripes and layout remain source-owned presentation. Default, Product and Embedded preserve their original hosts and anchors. RenderingIdentifier is the only standard parameter.

Before activation, read the existing documents Multilist and every actual child record. Verify exact direct-child membership and native enumeration order against the selected source order. Leave shared __Sortorder untouched wherever native enumeration already matches; correct only proven ordering differences without overwriting conflicting author edits. The frozen native receipt contains 134 rows across 26 tables, all already direct children, so no item moves or document-field additions are required. Keep existing Multilist definitions/values for rollback; do not delete them in this migration.

The .graphql rendering query now requests only datasource identity. Component data must come from enrichDocumentComponentMap in document-automatic-server.props.ts, initialized with the same Sitecore client and preview/authoring fetch options as the rest of the page. Runtime templates and shared sort-field identities are grounded in native receipts; this source change does not claim the native query or editing-host acceptance is complete.

The adjacent manifest and captured HTML remain unchanged historical witnesses. The source-oracle test adapts captured field values to synthetic automatic results only inside the test harness; production does not import those witnesses. Approved local document destinations continue through prospectusLinkField and the existing inventory/navigation boundary, preserving native target and encoded query/fragment behavior. External or unverified documents remain unavailable as before.
